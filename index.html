use case 1 · ai agent memory

Store, recall by semantic similarity, watch for new memories

Mixed text + 768-dim embedding column. KNN over the vector axis. Subscribe to get push events when new memories arrive.

Python SDK
from cuttledb import CuttleDB, ColType

with CuttleDB.connect("127.0.0.1", 7780) as db:
    hid = db.open()
    tid = db.create(hid, "memory", [
        ("text",      ColType.STRING),
        ("embedding", ColType.VEC, 768),
    ])

    # Store engrams
    db.insert(hid, tid, ["recipe: tomato risotto", [0.31, ...]])
    db.insert(hid, tid, ["recipe: chicken salad",  [0.28, ...]])
    db.insert(hid, tid, ["meeting note: q4 plan", [-0.12, ...]])

    # Semantic recall — AVX2 cosine + partial sort
    hits = db.knn(hid, tid, col=1, k=3,
                   query=[0.30, ...])
    # → [(0, 0.97), (1, 0.94), (2, 0.61)]

    # Watch the table for new memories
    db.sub(hid, tid)
    for evt in db.stream_events():
        print("new memory:", evt.row_id, evt.op)

use case 2 · real-time ui

One backend writes, every subscriber gets pushed in microseconds

UI tab opens a connection + subscribes. Backend pushes events into the same table. Every UI tab updates instantly, no polling. LOG ring buffer lets a reconnecting tab replay missed events.

Browser (WebSocket)
import { CuttleDB } from "cuttledb";

const db = new CuttleDB({
    transport: "ws",
    url: "ws://localhost:7780"
});
await db.connect();

const hid = await db.open();
const tid = await db.create(hid, "events", [
    ["user", 2],
    ["kind", 2],
    ["ts",   4],   // DATETIME
]);

// Subscribe — receives every INS/UPD/DEL
db.on("event", (evt) => {
    appendToDashboard(evt);
});
await db.sub(hid, tid);
Wire — UI tab side

# Subscribed again, no events missed.
use case 3 · hybrid retrieval

BM25 + vector + Boolean filters in one wire roundtrip

RRF fuses lexical and vector rankings server-side. Boolean DSL composes filters, scoring atoms (col~"phrase", col~V[...]), and predicates (col>5) with AND/OR/parens.

Python SDK
# Hybrid: vector + BM25 fused via Reciprocal Rank Fusion
hits = db.search(
    hid, tid,
    vec_col=1, text_col=0, k=5,
    vec=[0.12, 0.20, ...],
    query="brown fox",
)

# Boolean DSL: filters + scoring atoms composed
#   (kind="playbook" OR kind="ref")
#       AND embedding ~ [0.1,0.2,...]
#       AND uses > 3
hits = db.bsearch(hid, tid, 5,
    '(2="playbook" OR 2="ref")'
    ' AND 1~V[1.0|0.0|0.0|0.0]'
    ' AND 3>3'
)
# Server combines: predicate filter → KNN candidates →
#  BM25 candidates → RRF fuse → top-k. One roundtrip.
Wire — single roundtrip
>SEARCH 0 0 1 0 5 0.12|0.20|... ||| brown fox<+OK [2:0.0328;0:0.0312;5:0.0163]
# Boolean DSL:
>BSEARCH 0 0 5 (2="playbook" OR 2="ref") AND 1~V[1.0|0.0|0.0|0.0] AND 3>3<+OK [0:0.0328;2:0.0312]
# All five modes go through the same wire dispatcher:
#   KNN  ·  LSEARCH (BM25)  ·  SEARCH (RRF)
#   BSEARCH (Boolean)  ·  KNN ... WHERE

Why CuttleDB?

Most modern stacks pull in three or four databases to do what one process can do at the substrate level. CuttleDB collapses them.

⚡

Substrate-level speed

Column store with running aggregates. COUNT and SUM are O(1). AVX2 SIMD predicate scans. Wins read-path aggregates over SQLite :memory: at 1K-row workloads despite paying for TCP round-trips.

⊹

Vector search built-in

First-class VEC columns + HNSW index. Top-10 over 10K vectors in 2 ms. At 100K × 128: 12.7× faster than the AVX2+FMA brute-force baseline. No Pinecone, no separate service.

⇄

Real-time push

SUB / UNSUB per-table change feed. Every mutation triggers a >EVT line on every subscribed socket. LOG ring buffer (1024 events) for replay after disconnect.

🔒

Enterprise security tier

Multi-token auth, NDJSON audit log, TLS, --max-conn DoS cap, rate limit, structured slow-query log, HTTP /health probe, Prometheus /metrics.

⛁

Durable, transactional

ACID transactions: BEGIN / COMMIT / ROLLBACK. Write-ahead log with CRC32 frames + mid-transaction kill replay (exercised by integration tests).

⌂

One self-contained binary

Under 1 MB per platform. No JVM, no Python on the server side, no Redis, no SQLite library. Copy the binary, run it. Multi-platform CI: Linux + macOS + Windows.

Architecture

One binary, no daemon hierarchy, no embedded language interpreter. Everything below is the same process, the same heap.

1K-row aggregates: CuttleDB (TCP) vs SQLite (in-process)

Honest framing: CuttleDB pays for a TCP round-trip per query; SQLite runs inside your process. CuttleDB still wins read-path aggregates 1.4–1.8× despite the network handicap — but loses bulk INSERT 8.4× because the per-row TCP cost dominates a small in-memory load.

8.4× wins

Verify a release

Every binary ships with a sigstore .cosign.bundle — signature + cert + Rekor transparency-log inclusion proof. 

# 1. Checksum
sha256sum -c SHA256SUMS.txt

# 2. Signature (requires cosign v2.0+)
cosign verify-blob \
  --bundle cuttledb-server-linux-x64.cosign.bundle \
  --certificate-identity-regexp ".*" \
  --certificate-oidc-issuer-regexp ".*" \
  cuttledb-server-linux-x64

Cross-reference Rekor entries at search.sigstore.dev. Full security policy: SECURITY.md.
